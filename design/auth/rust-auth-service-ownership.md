# Design: Rust Auth Service Ownership

Status: authoritative implementation ownership after WO-02.

## Boundary

The Rust runtime owns Auth HTTP routes, native-IDL RPC dispatch, SQLite
repositories, context issuance/verification, NATS Auth Callout, post-commit
delivery, built-in participants, and embedded Portal/Console assets. TypeScript
packages provide clients and browser/device/service runtimes only.

## Source And Generation

- `crates/runtime/contract.trellis` owns the Auth contract.
- `crates/runtime/src/platform/auth/` owns domain behavior and adapters.
- `crates/runtime/src/storage/sqlite/platform/` owns the fresh schema.
- `crates/protocol/` owns signed context and proof verification.
- `crates/protocol-wasm/` exports the minimal shared verifier boundary.
- `crates/trellis/src/internal_sdk/generated/` and
  `ts/packages/trellis/internal_sdk/generated/` are generated, never edited.
- `crates/runtime-apis/` embeds canonical Auth/State and built-in web built-in
  package/participant semantic evidence generated by `cargo xtask install`.

## Composition

Startup opens and migrates Auth SQLite, validates the online issuer seed,
installs canonical built-in participants, ensures first-admin account flow,
rebuilds context/revocation KV mirrors, starts Auth HTTP/RPC/Callout/event
subsystems, and reports readiness only after required publication succeeds.

Fresh initialization atomically creates the protected administrator, accepted
built-in authority, and bundled public-client registrations before provider
admission. The username defaults to `admin`. An explicit initial password installs
its verifier; otherwise the username is reserved with no password verifier and
initialization issues a one-time `password_reset` flow. The replay response is
sealed under existing OAuth custody in the same initialization transaction.
The browser changes credentials, never creates administrator authority.

Password-reset flows record issuance authority: an ordinary authorization session
or the local operator. Ordinary RPC issuance still rejects the protected admin.
Local initialization/recovery may issue its reset; redemption checks the bound
principal, credential revision, protection status, token expiry, and portal CSRF.
Until the protected administrator sets a password, each startup prints a fresh
setup link before provider admission and revokes earlier pending links. After
setup, restart preserves credentials and emits no link; established-password reset
requires explicit local recovery.

The runtime configuration contains only online issuer seed path and context/JWT
policy. Offline root, certificate, manifest, and trust-floor configuration and
CLI tooling do not exist.

## Repository Rules

Repositories expose aggregate transactions rather than independent write
sequences. Administrative authorization, expected-revision checks, idempotency,
state changes, context revocations, events, and kick intents commit together.

Installed participant revisions and signed contexts are immutable. GrantBinding
is the sole current authority record. Login sessions are user-only. Resource
evidence is exact and server-owned.

## HTTP And NATS

HTTP bootstrap accepts identity/proof inputs and returns server-owned shared
installation data. Browser bind creates only a login; refresh returns
authorization. Device enrollment and device bootstrap remain distinct.

Auth Callout resolves signed context by digest, verifies the route token and
connect proof, rechecks current issuable state, and emits exact NATS
permissions. Application request/event verification checks context digest,
matching redundant session key, proof, explicit revocation, and action grant.

## Post-Commit Delivery

The post-commit runtime drains durable actions. Context/revocation publication
uses create-or-exact-confirm semantics. Auth events are signed and published
through ordinary authorization with durable proof preparation. Connection kicks
occur only after the state/revocation transaction commits and do not roll back
it on operational failure.

## Removed Ownership

The runtime has no desired/materialized authority repositories, proposal or
reconciliation workers, trust registry, offline root tooling, universal native
session rows, client artifact admission, or TypeScript Auth server.
